# CodeMirror 사용 안내

Home Assistant Ingress의 **웹 UI 열기**에서 사용합니다. 별도의 외부 포트를
개방하지 않습니다.

## MDI 아이콘 자동완성·미리보기

YAML이나 JSON에서 `mdi:`를 입력하면 아이콘 이름을 검색할 수 있습니다.
예: `icon: mdi:lightbulb` 또는 `"icon": "mdi:home-assistant"`.
이름의 일부로 검색하며 일치하는 접두사를 우선 표시합니다. 목록에는 실제 아이콘이
함께 표시되고 방향키와 Enter 또는 클릭으로 선택합니다. Ctrl+Space로 다시 열 수 있습니다.
기존 `mdi:이름` 위에 마우스를 올리면 큰 아이콘과 이름이 표시됩니다.
모바일에서는 자동완성 목록의 아이콘으로 모양을 확인할 수 있습니다.

공식 `@mdi/svg` 7.4.47의 7,447개 아이콘을 사용합니다. 첫 사용 시 앱 내부의 아이콘
데이터를 불러오며 외부 CDN이나 HA 연결은 필요하지 않습니다. 설치된 HA의 아이콘 버전이
다르면 일부 이름의 지원 여부가 다를 수 있습니다. 주석에는 자동완성을 표시하지 않습니다.

## Jinja 템플릿 렌더링

파일을 열고 **템플릿 렌더링**을 누르면 선택한 영역을 Home Assistant의 실제
상태로 평가합니다. 선택 영역이 없으면 현재 문서 전체를 템플릿으로 보냅니다.
저장하지 않은 수정 내용도 평가하며 파일 저장이나 자동화 실행은 하지 않습니다.
YAML에서는 `{{ ... }}` 또는 `{% ... %}`가 포함된 템플릿 본문을 선택하세요.
문서 전체 실행은 YAML 항목을 개별적으로 해석하거나 YAML 따옴표를 제거하지 않습니다.

한 줄의 `{{ states('sensor.temperature') }}` 같은 표현식에 마우스를 잠시 올리면
결과 팝업이 나타납니다. `{% ... %}` 블록이나 `{# ... #}` 주석이 있는 문서는
호버를 사용하지 않으며, 필요한 문맥을 함께 선택해 렌더링하세요.
호버 결과는 최대 5초간 재사용합니다. 최신 값은 패널의 **다시 실행**으로 확인하세요.
여러 줄 결과·오류는 하단 패널에서 확인할 수 있고 모바일에서도 버튼으로 실행합니다.

`states()`, `state_attr()` 등은 HA의 현재 값을 사용하지만 `trigger`, `this`, 자동화
실행 중 생성된 변수는 자동으로 제공되지 않습니다. 필요한 변수는 선택한 템플릿의
`{% set ... %}`로 정의하세요. 결과는 실행 시점의 값이며 자동 갱신되지 않습니다.
편집하면 결과를 무효화하고, 파일 전환 시 패널을 닫습니다. 요청은 64 KiB 이내이며
동시에 하나만 처리합니다. 시간 초과나 연결 오류는 패널에서 확인 후 다시 실행하세요.

구현은 [Home Assistant 공식 템플릿 REST API](https://developers.home-assistant.io/docs/api/rest/)
를 사용하며, Supervisor 토큰은 앱 서버 내부에만 보관합니다.

## 옵션

| 옵션 | 기본값 | 허용되는 동작 |
| --- | --- | --- |
| `allow_local_apps` | `false` | `/addons`의 로컬 앱 파일 조회·편집·업로드 |
| `allow_media` | `false` | `/media` 조회·편집·업로드 |
| `allow_addon_configs` | `false` | `/addon_configs`의 전체 앱 설정 조회·편집·업로드 |
| `allow_ssl` | `false` | `/ssl` 인증서·키 파일 조회·편집·업로드 |
| `allow_share` | `false` | `/share` 조회·편집·업로드 |
| `max_upload_mb` | `32` | 파일당 업로드 한도, 1–512 MiB |

`/config`의 Home Assistant 설정은 항상 접근할 수 있습니다. 추가 디렉터리는
항상 마운트하지만 앱은 옵션이 `true`인 경로만 허용합니다.
**구성**에서 필요한 옵션을 변경하고 저장·재시작하세요.

## 파일 편집

1. 통합 트리에서 `/config`, `/media` 등 경로를 펼칩니다. 허용된 경로만 표시됩니다.
2. 트리에서 파일을 선택합니다. 폴더를 클릭하면 펼치거나 접습니다.
3. 파일마다 탭이 열립니다. 편집 후 **Save** 또는 Ctrl/Cmd+S로 현재 탭을 저장합니다.
4. 기존 내용은 같은 디렉터리의 `파일명.backup`에 보존합니다. 다음 저장에서
   이 백업은 직전 버전으로 교체됩니다. 백업 실패 시 원본 저장도 중단됩니다.

YAML과 JSON의 구문 오류는 저장을 차단하며 **Restore Valid State**로 복원할 수
있습니다. `/config`의 YAML 저장 후에는 Home Assistant 설정도 검사합니다.
이 검사가 실패해도 저장된 파일을 자동으로 되돌리지는 않습니다.
다른 작업 경로의 YAML과 Markdown은 HA 전체 설정 검사를 실행하지 않습니다.

## 파일 관리와 엔티티 자동완성

별도의 Workspace·업로드 폴더 선택기 없이 트리 선택을 사용합니다. 디렉터리를
선택하면 그 디렉터리, 파일을 선택하면 상위 폴더가 생성·업로드·붙여넣기 대상입니다.

트리에서 우클릭하면 **New file**, **New folder**, **Rename**, **Delete**, **Cut**,
**Copy**, **Paste**, **Upload files**를 사용할 수 있습니다. 모바일은 파일 영역의
**⋯**를 누르세요. 폴더 복사·이동·삭제는 하위 항목도 포함합니다. 루트 자체의 이름 변경과
삭제는 금지합니다. 삭제는 확인 후 영구 삭제하며, 복사·이동은 기존 항목을 덮어쓰지 않습니다.
열려 있는 미저장 파일에 영향을 주는 작업은 저장 후 실행하세요.

파일 트리에 포커스하면 화살표로 탐색하고 F2로 이름 변경, Delete로 삭제,
Ctrl/Cmd+X·C·V로 잘라내기·복사·붙여넣기, Shift+F10으로 메뉴를 엽니다.
클립보드는 현재 앱 페이지 안에서 유지됩니다. 같은 폴더로 복사할 때는 복사본 이름을
입력합니다. 작업당 최대 10,000개 항목, 깊이 32단계, 총 512 MiB를 지원합니다.
다른 파일시스템으로 이동할 때는 복사 완료 후 원본을 삭제합니다. 원본 삭제에 실패하면
두 위치에 남을 수 있으므로 오류 내용을 확인하고 트리를 새로고침하세요.

헤더의 **⋯** 메뉴에서 YAML 검사·리로드·재시작과 엔티티 기능을 실행합니다.
**Validate YAML**은 현재 YAML/JSON 구문과 저장된 HA 전체 설정을 검사합니다.
저장하지 않은 편집 내용은 HA 서버의 검사 대상이 아닙니다.
**Reload YAML**은 저장된 설정 검사 후 `homeassistant.reload_all`을 호출합니다.
같은 메뉴에서 **자동화·스크립트·그룹·Core 설정 다시 불러오기**를 각각 실행할 수
있습니다. Core는 `homeassistant:` YAML 설정을 다시 읽으며 Core 재시작과는 별도입니다.
개별 리로드에도 저장된 설정 검사와 미저장 변경 보호가 적용됩니다.
**Material Design Icons ↗** 링크는 아이콘 검색 사이트를 새 탭에서 엽니다.
**Restart HA**는 확인 후 저장된 설정을 검사하고 Home Assistant Core를 재시작합니다.
두 작업 전에 편집 내용을 저장하세요. 리로드는 리로드 가능한 설정에만 적용됩니다.
오류 상태 표시줄을 누르면 자세한 이유를 볼 수 있습니다.

YAML에서 `entity_id:` 값이나 `light.` 같은 ID를 입력하면 엔티티 드롭다운이
표시됩니다. Ctrl+Space 또는 **Entity suggestions**로 직접 열 수도 있습니다.
↑/↓와 Enter로 선택하고 Escape로 닫습니다. ID 일부와 한글 표시 이름으로 검색하며,
후보에 표시 이름과 `state_translated` 상태가 함께 나옵니다. 번역은 HA에 설정된
언어를 따르며, 조회 실패 시 원래 `state`를 표시합니다. **Refresh entities**로 목록을 갱신합니다.

`SUPERVISOR_TOKEN`과 앱의 `homeassistant_api`, `hassio_api` 권한으로 연결합니다.
API 토큰을 사용자 옵션에 입력할 필요가 없습니다. 엔티티 연결 실패는 헤더의 ⋯ 메뉴에
표시되며, 실패 시 이전 목록을 지워 오래된 정보를 제안하지 않습니다.

## Markdown

`.md` 및 `.markdown` 파일은 Markdown 구문 강조를 제공합니다.
**Preview Markdown** 버튼으로 미리보기를 켜고 끕니다. 작은 화면에서는 편집기와
미리보기가 위아래로 배치됩니다. 미리보기는 HTML을 정화하며 이미지·스크립트·폼을
불러오지 않습니다. 외부 HTTP(S) 링크만 새 탭으로 열 수 있습니다.

## 업로드

트리에서 대상 폴더를 선택한 뒤 파일을 화면에 드롭하거나 우클릭 메뉴의 **Upload files**를
누릅니다. 트리의 폴더에 직접 드롭하면 그 폴더에 저장합니다. 여러 파일과
바이너리 파일을 지원합니다.

**Upload folder** 또는 폴더 드롭은 브라우저에서 ZIP을 만든 후 서버에서 압축을
풀어 폴더째 생성합니다. 한 번에 폴더 하나를 처리하고, 기존 폴더와 병합하거나 덮어쓰지
않습니다. 폴더 전체의 압축 해제 크기는 `max_upload_mb` 이하, 항목은 최대 10,000개,
깊이는 대상 경로를 포함해 32단계입니다. 경로 탈출·링크·중복 경로·암호화 ZIP은
거부합니다. 압축 해제 실패 시 임시 파일을 정리하고 대상 폴더를 생성하지 않습니다.
드롭은 빈 폴더도 보존하지만, 폴더 선택기에서는 빈 폴더가 생략될 수 있습니다.

중복 이름은 자동으로 덮어쓰지 않습니다. 파일마다 결과를 표시하며 일부 실패 시
성공한 파일은 유지됩니다. 업로드 시작 시 선택한 대상을 고정하며 업로드 중 파일 관리 작업은 차단합니다.

## 문제 해결

- 경로가 보이지 않음: 해당 `allow_*` 옵션을 켜고 저장·재시작하세요.
- `not mounted`: Supervisor가 디렉터리를 마운트했는지 확인하세요.
- Access denied: 옵션, 실제 파일 권한, 심볼릭 링크/하드 링크 여부를 확인하세요.
- 파일이 너무 큼: 편집 한도는 4 MiB, 업로드 한도는 `max_upload_mb`입니다.
- 파일이 트리에 없음: `.backup`, 앱 임시파일, `.git`, `.storage`, `node_modules`,
  `__pycache__` 및 링크·특수 파일은 표시하지 않습니다.
- 파일 트리: 펼친 디렉토리만 조회하고 큰 폴더는 500개 단위로 더 불러옵니다.
  하위 폴더 전체를 미리 탐색하지 않습니다. 오류는 폴더 아래에 표시되며 다시 시도할 수 있습니다.
  외부에서 파일이 변경된 경우 새로고침하세요.
- HA validation unavailable: Supervisor/Core 연결을 확인하세요. 파일 저장 여부는
  상태 표시줄에서 별도로 확인할 수 있습니다.

## 언어와 탭

화면 설정에서 **Language / 표시 언어**를 자동·영어·한국어 중 선택합니다.
자동은 브라우저 언어를 따르며 새로고침 후에도 선택을 유지합니다. CodeMirror의
검색·바꾸기 UI도 함께 번역합니다. 문서·파일명·엔티티 ID는 그대로 유지합니다.
HA 엔티티의 번역 상태는 HA가 설정한 언어를 따릅니다.

각 탭의 내용, 커서, 스크롤과 실행 취소 기록은 전환 후에도 유지됩니다.
탭의 **×**를 누르면 닫으며, 미저장 변경 내용은 폐기 확인을 거칩니다.
탭에 포커스한 상태에서 좌우 화살표·Home·End로 전환하고 Delete로 닫을 수 있습니다.
파일 이동/이름 변경은 열린 탭의 경로에도 반영합니다. 비활성 탭의 미저장 내용도
삭제·이동과 HA 제어에서 보호합니다. 브라우저를 새로고침하거나 닫기 전에 저장하세요.
편집 내용은 서버나 localStorage에 자동 저장하지 않습니다.
